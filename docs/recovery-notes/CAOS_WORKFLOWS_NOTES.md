# Creatures Map Editor 1.08 — CAOS generation workflows

## Four UI commands, one shared writer

MFC recovery already identifies:

```text
00409FF0 CC2ERoomEditorDoc_OnInjectAsWorld
0040A090 CC2ERoomEditorDoc_OnInjectAsAddon
0040B730 CC2ERoomEditorDoc_OnExportAsAddon
0040B820 CC2ERoomEditorDoc_OnExportAsWorld
```

All four call:

```text
0040A130 CC2ERoomEditorDoc_WriteWorldOrAddonCAOS
```

with:

```text
false = World
true  = Addon
```

The Inject handlers feed the generated script through the live-game path.
The Export handlers create `!world.cos` / `!addon.cos` and use the same script
generator.

## Document script envelope

`CC2ERoomEditorDoc_WriteWorldOrAddonCAOS` writes the recognizable header:

```text
* Autogenerated by the Creatures Map Editor
* For more info see http://cdn.creatures.net
* World file: existing map deleted, CA rates written

or

* Addon file: deletes existing metarooms at the same place, same background name

* <metaroom count> metarooms, <room count> rooms, <door count> doors
```

It calls:

```text
00422AE0 C2EWorldModel_GetRoomCount
004242E0 C2EWorldModel_WriteWorldOrAddonCAOS
```

For **World** mode, it subsequently emits the complete CA rate table as:

```text
rate <roomType> <caIndex> <gain> <loss> <diffusion>
```

for all 16 room types × 20 CA indices.

Addon scripts deliberately do not replace the global CA rate table.

## WorldModel CAOS order

`004242E0 C2EWorldModel_WriteWorldOrAddonCAOS`

World mode starts with:

```text
mapd <mapWidth> <mapHeight>
```

Then each metaroom is created.

Addon mode skips global `MAPD`; before recreating each metaroom it calls the
addon replacement/preflight generator.

Both modes then:

1. create every metaroom and room;
2. write every generated `DOOR`;
3. write cleanup code for temporary `GAME` variables.

### Doors

The recovered door format is:

```text
door game "mapeditortmp_<roomId1>" game "mapeditortmp_<roomId2>" <permeability>
```

That connects directly to the already-recovered room creation helper.

## Room creation / temporary handles

`C2EEditorRoom_BuildInjectCAOS` writes:

```text
setv va00 addr ...
rtyp va00 <roomType>
rmsc <roomId> <roomId> "<track>"
setv game "mapeditortmp_<roomId>" va00
```

The `GAME` variable is a temporary handle used by later generated `DOOR`
commands.

`C2EEditorRoom_BuildDeleteCAOS` emits:

```text
delg "mapeditortmp_<roomId>"
```

This does **not** delete the room. It deletes the temporary `GAME` variable.

That clarifies the metaroom helper:

```text
004171E0 C2EEditorMetaRoom_WriteCleanupCAOS
```

which calls the room cleanup helper once per room after doors have been written.

## Metaroom creation

`00416F20 C2EEditorMetaRoom_WriteCreateCAOS`

requires at least one background and emits:

```text
setv game "mapeditortmp" addm <left> <top> <width> <height> "<background0>"
mmsc <centreX> <centreY> "<track>"
addb game "mapeditortmp" "<background1>"
addb ...
```

then calls `C2EEditorRoom_BuildInjectCAOS` for every room.

## Addon replacement semantics

`00416D00 C2EEditorMetaRoom_WriteAddonReplacementCAOS`

is only called in Addon mode.

Its generated CAOS:

1. `GMAP`s the editor metaroom centre;
2. if a metaroom already exists there, checks `BKDS` against the expected
   background;
3. refuses to replace a same-position metaroom with a different background;
4. scans agents and refuses replacement while a non-carried agent remains;
5. obtains existing room IDs via `ERID`;
6. `DELR`s every room;
7. `DELM`s the old metaroom.

The executable contains the exact warning text explaining both failure modes.

This makes the old autogenerated comment precise: an addon is intended to
replace its own previous instance safely, without deleting some unrelated
metaroom occupying the same coordinates.
